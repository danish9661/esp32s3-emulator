Run firmware

Pick a gallery example or load your own .merged.bin (arduino-cli produces one per sketch). Press Run — the emulator steps both cores, and output appears in the console as the firmware prints. Stop halts stepping; Reset reloads the same image from its first boot instruction. The steps-per-frame slider trades emulation speed against page responsiveness; the MIPS readout shows smoothed emulated instructions per wall second.

MicroPython REPL

The MicroPython preset in the firmware rail boots the stock v1.29.0 GENERIC_S3 interpreter to an interactive >>> prompt — no build needed. Paste an image URL (default: the upstream release .bin) and press ▶ REPL: the page downloads it, pads flash to 3 MiB, appends the littlefs vfs partition the firmware mounts (same recipe as tools/micropython_repl.sh), and loads it. Press Run and wait for >>> (tens of seconds: the interpreter is a ~35M-instruction boot). The preset flips the serial port to UART0 — the REPL listens there, not on USB-CDC — and offers print(6*7) as a first line; type any Python and press Enter. The same URL box boots a local copy: serve the .bin beside the page (same-origin fetch) or pick the file through Load merged.bin. Upstream micropython.org serves no CORS header, so a cross-origin fetch fails in the status line — self-host the file in that case.

Serial in and out

The console merges USB-CDC (Serial) and UART output. Search, copy, and clear act on the scrollback buffer, which holds the last 5000 lines. To send keystrokes, choose the port your firmware reads — USB-CDC for Serial sketches, UART1 for the echo example — type, and press Enter. Lines are sent with a trailing newline unless you hold Shift, matching what readStringUntil and REPL readers wait for. Long pastes are chunked under the 128-byte hardware FIFO depth, the way silicon drops overrun bytes.

Pin header

The header shows live levels for GPIO0–39. Amber means driven high, dim means low, blue marks pins switched to input view. Click any pin to flip its display between output and input. The levels come from the same GPIO matrix the firmware drives, including peripheral-routed signals such as PWM, RMT, and I2S — so a blinking LED sketch visibly blinks here.

Fixtures

Some gallery entries need a stand-in for hardware that cannot exist in a browser tab. The manifest declares them and the bench applies them before boot — the same values the headless harness feeds through environment variables:

TOUCH_INJECT=3:1877        touch pad 3 reads counter 1877
ADC_INJECT_MV=825           ADC1_CH3 (GPIO4) reads 825 mV
TEMP_C=25                   internal temperature sensor reads 25 °C
WIFI_SCAN_APS=...           fixture access points for the scan sketch
WIFI_STA_CONN=1             complete the station association
SPI_SDSPI=1                 attach the virtual SD card over SPI
FLASHENC_KEY=...            boot the image through XTS flash encryption

Nothing about the firmware changes — fixtures only answer the reads real hardware would answer.

Validate

The battery replays all 111 cases headlessly: build (or reuse) each merged image, boot it through run_flash or the Node bridge, and assert serial markers plus internal state. Run a slice locally with ./tools/run_battery.sh wifi_scan wifi_sta, or the whole suite with ./tools/run_battery.sh. The freshness guard (tools/check_firmware_freshness.py) keeps committed bins in sync with their sketch sources, and tools/webui_playwright.py drives the real page in Chromium — boot, MIPS, echo, UART round-trip, SD mount, touch read — failing loudly on any page error.
